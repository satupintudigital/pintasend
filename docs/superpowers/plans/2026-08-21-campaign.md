# Implementasi: Modul WA Campaign (2026-08-21)

Blast massal ratusan–ribuan penerima sebagai modul Wavio (produk sama), digate
`TenantAddon` key `campaign`. Penamaan konsisten "Campaign".

## Arsitektur

```
Dashboard/API ──► Campaign (draft) ──start──► CampaignRecipient (snapshot pending)
                                                ▲
workers/campaign-dispatch (HTTP on-demand) ─────┘
   claim batch → kirim OpenWA berjeda acak → update status per penerima
   → finalisasi → event webhook 'campaign.completed' (outbox WebhookDelivery)
```

Dispatch TIDAK berjalan di request Workers utama (batas eksekusi) — pola antrean
sama dengan WebhookDelivery.

## Perubahan

**Skema** (`prisma/migrations/2026-08-21-campaign.sql`, sudah diterapkan ke Neon):
- `Contact` — audiens per tenant; unik `(tenantId, chatId)`; tag JSON; opt-out.
- `Campaign` — template `{{nama}}/{{nomor}}/{{tanggal}}`, media opsional (URL),
  filter audiens by tag, jeda acak min/max, jadwal, statistik.
- `CampaignRecipient` — unit kerja dispatcher; status
  `pending|sending|sent|failed|skipped` (recovery 'sending' >10 menit → pending).

**Lib**: `src/lib/contacts.ts` (CSV RFC4180 parser + upsert chunk 200),
`src/lib/campaigns.ts` (CRUD + transisi status + resolve audiens chunk 500 +
render template), addon `campaign` masuk `tenantConfig` (KV cache).

**API publik v1**: `/v1/contacts` (GET/POST csv|tunggal), `/v1/contacts/:id`
(PATCH/DELETE), `/v1/campaigns` (GET/POST), `/v1/campaigns/:id`,
`/v1/campaigns/:id/{start|pause|resume|cancel}`.

**Worker baru** `workers/campaign-dispatch/` (deploy terpisah): batch 8/tick,
jeda acak [min..max] detik, cap harian 250/device (WIB), watermark footnote
kecuali addon remove_watermark, auto-pause saat device restriction/not-ready,
skip sisa penerima saat kuota bulanan habis, enqueue event completion.

**Dashboard**: `/dashboard/kontak`, `/dashboard/campaign` (+ API session
`/api/campaigns/*`); menu sidebar tampil hanya bila addon aktif;
event `campaign.completed` bisa disubscribe di WebhookPanel.

## Pengaman anti-ban

Jeda acak antar pesan · cap harian per device · opt-out dihormati saat resolve
audiens · auto-pause restriction · kuota per penerima (konsisten send-bulk).

## Deploy & test (2026-08-21)

- Worker **campaign-dispatch-wavio** sebelumnya ter-deploy dengan cron `* * * * *` (kini dinonaktifkan agar Neon dapat scale-to-zero); jalankan via HTTP on-demand.
- Free plan Cloudflare tidak mendukung `limits.*` dan invocation dibatasi ±30 dtk
  wall-clock → BATCH_LIMIT=4, gap antar pesan di-cap 6 dtk (≈240 pesan/jam/device).
- Secret terpasang: DATABASE_URL, OPENWA_BASE_URL, OPENWA_ADMIN_KEY, DISPATCH_TOKEN.
  Catatan: nilai `.env` ber-quote (`"…"`) — wajib strip quote saat pipa ke wrangler.
- E2E infrastruktur lulus: dry-run tanpa campaign → no-op; campaign running
  tanpa device valid → diklaim lalu auto-pause (`failReason: "device tidak ditemukan"`).
  Fixture uji sudah dibersihkan; addon `campaign` tetap aktif di tenant Wavio Demo.
